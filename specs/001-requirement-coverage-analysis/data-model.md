# Data Model: 要件カバレッジの自動判定

## エンティティ

### 要件（Requirement）

| 項目 | 型 | 規則 |
| --- | --- | --- |
| `id` | 文字列 | 必須。64字まで。文字、数字、`_`、`.`、`-` だけで、先頭は文字か数字。要件の中で一意 |
| `description` | 文字列 | 必須。空でない。120字まで |

### E2Eテスト（E2ETest）

| 項目 | 型 | 規則 |
| --- | --- | --- |
| `id` | 文字列 | 必須。64字まで。要件と同じ規則。テストの中で一意 |
| `description` | 文字列 | 必須。空でない |

### 判定（Judgment）

1つの要件と1つのテストの組についての結果。

| 項目 | 型 | 規則 |
| --- | --- | --- |
| `requirement_id` | 文字列 | 要件の `id` |
| `test_id` | 文字列 | テストの `id` |
| `score` | 数値（0〜1） | モデルの noul の値。1 に近いほど「はい」 |
| `verdict` | `yes` または `no` | `score >= 0.5` なら `yes` |
| `confidence` | 数値（0.5〜1） | `max(score, 1 - score)` |

### カバレッジ（Coverage）

要件ごとの集計。

| 項目 | 型 | 規則 |
| --- | --- | --- |
| `requirement_id` | 文字列 | 要件の `id` |
| `covered` | 真偽 | `yes` の判定が1件以上なら真 |
| `matched_test_ids` | 文字列の列 | `verdict` が `yes` のテストの `id`（`score` の降順） |
| `matched_count` | 整数 | `matched_test_ids` の数 |
| `confidence` | 数値または null | カバー済みなら、一致したテストの最高の確信度。未カバーは null |
| `level` | `high`、`medium`、`low`、`needs_review` | 確度が 0.9 以上で high、0.7 以上で medium、それ未満で low。未カバーは needs_review |

### どの要件にも対応しなかったテスト（UnmatchedTest）

どの要件でも「はい」と判定されなかったテスト。`id` と `description` を持つ。入力の順。

### 実行（Run）

| 項目 | 型 | 規則 |
| --- | --- | --- |
| `run_id` | 文字列 | 実行フォルダの名前。`[A-Za-z0-9._-]{1,64}` |
| `status` | `succeeded` または `failed` | 結果の置き場所のファイルで表す |
| `started_at`、`finished_at` | 日時 | レポートの `meta` に残す |
| `model` | 文字列 | モデルの名前とリビジョン |

## 関係

```text
要件 1 ── N 判定 N ── 1 E2Eテスト
要件 1 ── 1 カバレッジ
実行 1 ── N 判定、N カバレッジ
```

## 検証の規則

- 要件、テストのどちらかが0件なら、実行は失敗する。
- 要件が100件、またはテストが100件を超える場合は、実行は失敗する（上限の超過）。
- `id` が重複する場合や、`id` の形が規則に合わない場合は、実行は失敗する。
- `description` が120字を超える場合、ファイルが128 KB を超える場合は、実行は失敗する。
- 失敗の理由は、`FAILED.json` に書く。
- 判定の総数は、要件の数 × テストの数と一致する（SC-003 の確認に使う）。
